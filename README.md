# asnkar

## asnips.py

Получает IPv4-подсети указанной ASN и сохраняет в `asn<номер>_cidr.txt`
в текущем каталоге. Нужны Python 3.8+ и доступ к интернету; сторонние библиотеки
и API-ключи не требуются.

```bash
python3 asnips.py 9123
```

Можно также указать `AS9123`. Результат — `asn9123_cidr.txt`: один IPv4 CIDR
на строку, без дублей, с сортировкой по адресу. Повторный запуск заменяет файл.
Если у ASN нет IPv4-анонсов, создаётся пустой файл. Ошибка запроса не меняет
существующий файл и завершает программу с кодом 1.

Источник: [RIPEstat RIS Prefixes](https://data.stat.ripe.net/docs/data-api/api-endpoints/ris-prefixes).
Используется последний доступный BGP-снимок RIS: только префиксы, для которых
эта ASN является источником анонса. IPv6 и транзитные маршруты не включаются.

## scanner.py

Python 3.11+. Установка и запуск:

```bash
python3 -m pip install -r requirements.txt
python3 scanner.py asn9123_cidr.txt
```

Сканер лениво перебирает все IPv4-адреса из CIDR-файла. Также можно указать
отдельные IPv4 без `/32`; пустые строки и комментарии `#` игнорируются.
Пересекающиеся диапазоны объединяются, каждый IP проверяется один раз.
Включаются все адреса диапазона, в том числе его начало и конец.

Для каждого IP:

1. Подключается к порту 443 без SNI и читает CN сертификата.
2. Запрашивает A-записи CN через системные DNS-серверы; CNAME обрабатывается
   DNS-резолвером. Положительные и отрицательные ответы кэшируются с учётом TTL.
3. Если проверяемый IP входит в A-записи — `original`, пропускает его.
4. Если A-записи есть, но IP в них нет, повторяет TLS-подключение к тому же IP
   с SNI, равным CN. Проверяет имя по SAN, срок, подписи и доверие цепочке
   через публичный CA-набор `certifi`.
5. Проверяет, что оба подключения вернули один и тот же сертификат.
   Если все условия выполнены — `DETECTED`.

`detected.txt` содержит только IP, по одному на строку. `detected.jsonl` содержит
CN, A-записи, порт, SHA-256 сертификата, издателя, срок и время проверки каждого
детекта. Оба файла заменяются при запуске; каждый детект сразу записывается
на диск, поэтому Ctrl+C сохраняет уже полученные результаты. `scanner.log`
ведётся через loguru с ротацией. Прогресс выводится каждые 5 секунд.

```bash
python3 scanner.py asn9123_cidr.txt --workers 100 --timeout 5 --dns-timeout 5
python3 scanner.py scan_test_cidr.txt --workers 3 --verbose
python3 scanner.py ranges.txt -o found.txt --details found.jsonl --log found.log --port 443
```

Ошибки DNS, отсутствие A-записей или CN, wildcard CN (`*.example.com`),
недоверенный/просроченный сертификат, несовпадение имени и смена сертификата
при SNI не считаются детектами. Причины пропуска видны с `--verbose`.
Автоматические HTTP-запросы и сравнение HTML в этот критерий не входят.

`DETECTED` означает совпадение с описанной эвристикой: валидный сертификат
домена на IP вне его текущих A-записей. Так могут выглядеть и обычные CDN,
резервные серверы или reverse proxy; наличие VPN или конкретного протокола
этот сканер не подтверждает. Отзыв сертификата через CRL/OCSP не проверяется.

Локальные тесты без сетевых запросов:

```bash
python3 -m unittest discover -v
```

## GitHub Actions

Workflow **Scan AS9123** запускается при push в `main` или вручную:
**Actions → Scan AS9123 → Run workflow**. Для ручного запуска можно выбрать
параллельность и таймаут. SSH и дополнительные secrets внутри Actions не нужны.

Каждый запуск сначала выполняет тесты и заново получает IPv4-префиксы AS9123
из RIPEstat. Четыре задания сканируют непересекающиеся части одного снимка
адресов. По умолчанию каждое использует 100 workers и таймаут 5 секунд.
Обычный локальный запуск `scanner.py` по-прежнему сканирует весь входной файл.

На странице завершённого запуска в **Artifacts** доступен итоговый архив
`asn9123-results-<run_id>-<attempt>`:

- `asn9123_cidr.txt` — актуальные подсети именно этого запуска;
- `detected.txt` — объединённый список IP без дублей;
- `detected.jsonl` — данные сертификатов и DNS;
- `summary.json` и `summary.md` — итог и признак полноты сканирования;
- `shards/` — логи и исходные результаты каждой части.

Итоговый архив хранится 30 дней, промежуточные артефакты — 7 дней.
На одну часть выделено до 5 часов сканирования. При ошибке или таймауте
частичные результаты загружаются, итог помечается `PARTIAL`/`complete: false`,
а workflow завершается с ошибкой. Частичный скан не выдаётся за полный.
Немедленная ручная отмена всего workflow может прервать и загрузку артефактов.

Для самостоятельного распределения скана доступны `--shard-count N` и
`--shard-index I`, где `I` начинается с 0. Части нужно запускать с одним
CIDR-файлом, одинаковым `N` и разными выходными файлами.
